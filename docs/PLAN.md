## 3. 작업 계획
| 미션 | 쪼갠 작업 단위 | 확인 방법 | 예상 위험 |
|---|---|---|---|
| M1 | 테스트 설계, 코드 작성, 검증까지의 실행 단계 | 설계한 테스트 케이스와 실제 테스트 결과를 비교하고 R5 및 Mutation Test로 검증 | 요구사항 누락, 잘못된 기대값 설정, 예외 케이스 누락, 테스트 검증 부족 |

| M2 | 기존 테스트 측정 > 코드 리뷰 > 결함 발견 > 개별 실행 검증 > 테스트 개선 > 전후 비교 | 기존 AI 테스트와 개선된 테스트를 비교하고, 개별 테스트 실행 및 변이 점수 변화를 통해 결함 탐지 능력 확인 | 테스트 결함 누락, 잘못된 기대값, 개선 테스트 작성 오류, 변이 점수 향상 실패 |

| M3 | 계약서 분석 > 테스트 케이스 설계 > 결제 테스트 > 취소·환불 테스트 > 시간 초과 및 재시도·동시 요청 검증 > 변이 테스트 | 정상·실패·예외 상황별 테스트를 실행하고 주문 상태, 결제 기록, 재고, PG 호출 횟수를 종합적으로 검증한 후 Mutation Test 점수 확인 | 테스트 케이스 누락, 상태 변경 검증 오류, 동시 요청 및 재시도 테스트 부족 |

| M4 | 파일별 반복 실행 > 초기 실패율 측정 > 원인 분석 > 테스트 코드 수정 > 반복 실행 > 결과 기록 | 모든 불안정 테스트를 30회 이상 반복 실행하고, 수정 전후 실패율을 비교하여 안정화 여부 확인 | 실행 타이밍 문제, 비동기 처리 오류, 테스트 간 데이터 간섭, 원인 분석 오류 |

| M5 | 계약서 분석 > 조회·자동 취소 테스트 작성 > 전체 Mutation Test > 생존 변이체 분류 > 미탐지 결함 분석 | m5 테스트와 전체 Mutation Test를 실행하고, 살아남은 변이체를 분류한 뒤 계약서의 모든 규칙에 대한 결함 탐지 여부 확인 |  테스트 누락, 코드 수정 실수, 변이체 분류 오류, 실행 결과 확인 누락 |

## 4. 안전장치 (우리 팀이 지킬 것 3가지)
1. 문제가 발생하면 혼자 판단하지 않고 팀원과 공유한다.
2. 다른 팀원의 작업 영역을 임의로 수정하지 않는다.
3. 테스트 결과와 변경 사항을 투명하게 공유한다.
