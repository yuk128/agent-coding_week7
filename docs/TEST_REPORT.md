## 3. 커버리지가 높은데 변이 점수가 낮았던 이유 (우리 팀의 결론)
- AI가 만든 테스트는 줄 커버리지가 97.57%로 코드를 거의 다 실행했지만, 변이 점수는 58.2%로 심어 둔 결함 189개 중 79개를 놓쳤다.
- 줄 커버리지는 "코드가 실행됐는가"만 알려 주고, "결과가 올바른지 검사했는가"는 알려 주지 않기 때문이다.
- 분기 커버리지도 ai_tests는 81.34%로 줄 커버리지(97.57%)보다 낮아, 조건문의 한쪽 경로만 실행한 곳이 많았다.
- 우리 테스트는 줄 커버리지 100%에서 변이 점수 98.4%를 기록했다. 차이를 만든 것은 테스트 개수가 아니라 단언의 질이다. 계약서에서 가져온 구체적인 값을 비교했고, 오류 코드와 "실패했을 때 바뀌면 안 되는 것"(재고·주문·PG 호출 횟수)까지 확인했다.

## 4. 한계와 남은 위험 (3가지)
1. 변이 점수 98.4%는 공개 도구가 만든 결함 기준이라, 채점용 숨은 결함에서는 다를 수 있다.
2. 계약서에 정의가 없는 동작은 기대값의 근거가 없어서 테스트하지 못했다. (담은 뒤 상품이 삭제된 장바구니의 조회, 결제 기록 id의 번호 형식 — 생존 변이체 cart#35, payment#5·#6)
3. 시간과 동시성은 가짜 시계와 모의 PG로만 검증했다. 실제 PG의 지연이나 실제 동시 접속과는 다를 수 있다.
